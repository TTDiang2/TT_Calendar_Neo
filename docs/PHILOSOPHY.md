# 设计哲学

## §1 数据主权

日历是最私人的数据之一。本项目**没有服务器**：数据存在每台设备本地的
SQLite 里，设备间的流动只经过**用户自己的 GitHub 私有仓**。
我们（开发者）看不到、碰不到、也丢不掉你的数据。

## §2 双轨分离

- **数据同步**：用户数据 ↔ GitHub 数据仓（REST 协议，见 SYNC_PROTOCOL.md）
- **代码同步**：git 仓库本身

应用**永不**自动 commit/push 代码仓；同理它也不做代码仓与数据仓的耦合。
数据仓就是数据仓，代码仓就是代码仓。

## §3 一切外部数据源都是订阅

节假日、股价、课程表、转债打新……在模型里都是同一张 `subscriptions` 表
（见 SUBSCRIPTION_SPEC.md）：登记 `url + 抓取规则` → 抓取产物统一变成
events。用户不需要为每种数据源学一套 UI，agent 按登记信息现场写适配。

## §4 三端同构

Web / Windows / iOS 共享**同一份** React UI 与**同一份**数据门面代码。
端差异被压缩到两个注入点：数据传输（HTTP 或 Worker 本地库）与原生壳
（浏览器或 Tauri）。任何功能改动天然三端生效。

## §5 纯函数内核

视图聚合、三方合并、农历换算、忙度算法全部是零 IO 纯函数
（`packages/domain`），行为用 golden 测试冻结。重构随时可做，
语义漂移会被当场拦下。

## §6 农历是一等公民

不是「附加显示」：倒数日支持 `repeat_type='lunar'` 按农历月日重复，
Day 节点直接携带农历显示串。春节生日和排查日同样是一等日程。

## §7 面向 agent 协作

- 契约用 zod 描述（`packages/contracts`），机器可校验
- 领域层零 IO，agent 可独立测试后再接入
- 订阅登记（`status='pending'`）就是给 agent 的任务单：读 url/rules_text →
  现场写适配 → 置 active。应用的扩展方式是「写代码的数据源适配器」，
  而不是「让用户配爬虫」
